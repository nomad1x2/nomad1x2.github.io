Task 2 - The hunt continues - (Network Forensics)

With your help, the team concludes that there was clearly a sophisticated piece of malware installed on that endpoint that was generating some network traffic. Fortunately, DAFIN-SOC also has an IDS which retained the recent network traffic in this segment.

DAFIN-SOC has provided a PCAP to analyze. Thoroughly evaluate the PCAP to identify potential malicious activity.

Downloads:

  • PCAP to analyze (traffic.pcap)

    • Prompt:

  • Submit all the IP addresses that are assigned to the malicious device, one per line

    • Solving the task:

    I actually solved this one with an unintentional cheese and then had to re-scan the PCAP for the intended path -- writeup below, cheese follows.

    This task actually wasn't that difficult if you understand that the NSA wouldn't allow the answer to be in plain sight, i.e., there is no way that the answer would be the sources and destinations of frames in the PCAP, right?

    With this in mind, we'd need to check the actual frames' content. Since the PCAP is actually very small, it doesn't take too long to look into each packet, and I was able to identify that a majority of the packets are either ARP, SSH, or FTP data. Since we can't get too much from ARP with the context given, and SSH is encrypted, we can filter the PCAP for FTP data:

    This breaks down the PCAP even further and filters out only 132 packets, and from here the answer was easy to find. Scrolling through the PCAP, we see that the device switched to FTP Passive Mode and transferred router configs (but we find no actual router configs here):

    This had to be it, but what is Passive Mode? Reading from the IBM link posted above, the answer was clear:

  • 1. There are 6 numbers in each passive mode response 227:

    • Router1_backup.config: (172, 16, 1, 5, 66, 33)

    Router2_backup.config: (172, 16, 1, 5, 100, 87)

    Router3_backup.config: (172, 16, 1, 5, 197, 63)

  • 2. The first four are the IP address:

    • 172.16.1.5

  • 3. The 5th and 6th numbers are the port, with the 5th number multiplied by 256 added by the 6th number:

    • Router1_backup.config: 66 * 256 + 33 = 16929

    Router2_backup.config: 100 * 256 + 87 = 25687

    Router3_backup.config: 197 * 256 + 63 = 50495

    The solution:

    I tried all of the unique addresses we found, but I was met with the Sorry, that's not right. error. Then I had to think a little smarter -- only one config had an interface labeled with "to_openwrt2" which was the Router3_backup config. OpenWrt is a Linux‑based open‑source platform designed for embedded systems, and it’s mainly used on small devices to handle and direct network traffic. That seemed pretty suspicious to me, so I submitted each unique IP on that device to get the solve: 127.3.9.3, 192.168.3.254, and 192.168.5.1
